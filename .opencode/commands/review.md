审查当前未提交的改动，**不要修改任何文件**，只输出问题清单。

先看改动范围：

!`git status --short && git diff --stat`

然后逐项检查：

1. **硬边界**：`src/core` 里有没有框架依赖（vue/pinia/element-plus）、有没有 DOM/存储直连、有没有反向依赖 UI 层。
2. **Schema 一致性**：改动的类型是否与 `docs/一期-技术方案.md` §2.2 一致；是否有新增字段没同步文档。
3. **数据流**：表单值是否统一走 `getByPath`/`setByPath`；是否存在手工拼路径字符串。
4. **历史记录**：所有写 schema 的操作是否都经过 `commit()`；输入类改动是否 debounce。
5. **拖拽引用**：clone 是否深拷贝 + 新 id。
6. **可测性**：新增的 core 纯函数是否有对应单测。
7. **范围**：有没有夹带任务清单之外的功能（尤其审批流、版本化、用户体系）。

输出格式：按 `阻断 / 建议 / 可忽略` 三级列出，每条给文件名 + 行号 + 一句话理由。
没有问题就直接说"未发现阻断项"。$ARGUMENTS
